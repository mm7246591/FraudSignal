# 風險規則研究與設計（步驟 3）

整理日期：2026-10-15。範圍：台灣常見的**假投資**與**假購物／假送物**，平台為 Threads（研究與實測樣本都來自 Threads），同一套規則也用在 X。

## 1. 研究摘要

### 1.1 Threads 上的詐騙現況

- 打詐專法要求廣告實名制後，詐團改用 Threads 的**一般貼文**規避監管（「貼文就可能不算是投廣告」），民眾較難察覺帳號真偽。〔數發部〕
- 熱門話題：演唱會門票、韓星周邊、公仔、農產品（水果）、二手買賣、免費送 iPhone／Switch 2／PS5。〔數發部、刑事局〕
- 典型流程是**一條鏈**，不是單一字眼：
  1. 貼文誘餌（低價、免費送、轉售門票、產地直送）
  2. 留言或私訊後，導到 LINE「客服」
  3. 給偽冒超商網站連結（7-11 賣貨便、全家好賣+）
  4. 跳出「實名認證未通過／帳號凍結／未完成金流簽署」
  5. 要求匯款、無卡提款、信用卡、OTP
- 2026 年 1～2 月，「7-11 賣貨便」遭冒用占網路購物詐騙案件 74.3%。〔mrmad 引述警方〕

### 1.2 假投資（證交所三型、金管會五態樣、165）

| 類型 | 常見話術／特徵 |
|---|---|
| 保證獲利型 | 保證獲利、穩賺不賠、假對帳單、獲利截圖、AI 深偽名人影片 |
| 生活化誘餌型 | 免費贈書、知識分享、公益、求職，再拉進 LINE 群由「理財導師」帶 |
| 偽冒交易平台 | 假 App 可「插隊搶漲停」，小額出金後以防洗錢、稅金為由不給大額提領 |
| 群組勸誘買股 | 推薦飆股、加入 LINE 群、投顧老師、助理、暗樁假學員貼對帳單 |
| 虛擬貨幣 | 高收益、USDT（泰達幣）、搬磚套利、幣商 |
| 冒名 | 冒用名人或金融業者；**冒名帳號會在簡介加「小心詐騙、不會要求粉絲匯款」等反詐字眼取信** |

165 的明確說法：「保證獲利」「穩賺不賠」一定是詐騙；投資要你加 LINE 一定是詐騙。

### 1.3 假購物／假送物

- 免費送 iPhone、筆電、媽祖結緣品 → 加 LINE → 假賣貨便 → 「未完成金流簽署」→ 假客服。〔刑事局〕
- 水果特賣：「自家果園直供」「產地現採現寄」「因盛產推出優惠」「支持小農」，價格明顯低於行情，留言後被導到 LINE 客服。〔數產署〕
- 倒店出清、新開幕免費送、盜用實體店面街景照片。〔刑事局〕
- 演唱會門票轉售：導到 LINE，給假賣貨便連結。〔警方〕
- 警方列為「百分之百詐騙」的字眼：**金流驗證、解除限制、無卡提款資訊**。這些多出現在私訊對話，貼文較少見。

### 1.4 可用的公開資料

| 資料 | 內容 | 授權 |
|---|---|---|
| [165反詐騙諮詢專線_遭停止解析涉詐網站](https://data.gov.tw/dataset/176455) | 約 2,000 筆網域與網站性質（金融保險、電子商務、運輸倉儲…），含大量 `myship-711-com-tw-xxx.shop` 這類仿冒網域；2026-10-14 更新 | 政府資料開放授權條款第 1 版 |
| [165反詐騙諮詢專線_假投資(博弈)網站](https://data.gov.tw/dataset/160055) | 網站名稱、網址、件數 | 同上 |
| [Cofacts 開放資料](https://github.com/cofacts/rumors-db/tree/master/opendata) | 民眾回報的可疑訊息與查核回覆，含大量詐騙訊息 | CC0 |

165 詐騙 LINE ID 資料集已在 2024-11 下架，不能用。

### 1.5 賣家特徵研究

交大以 Yahoo 拍賣資料做詐騙偵測（Accuracy 97.67%），有關的特徵是**賣場存活時間 < 5 天、賣家評價 < 44**、可面交但不可貨到付款、價格 3,000～20,000 元。重點是：判斷依據多半是**帳號與交易條件**，不只是文字。Threads 貼文上看不到帳號建立時間與評價，所以這類特徵目前用不到。

### 1.6 互動數（讚、留言）

- 研究指出互動數可以向 bot 購買，bot 留言短且彼此相似。
- 詐騙貼文被檢舉下架後會快速以相同內容重新上架，所以新貼文的互動數通常很低，跟一般小賣家一樣。
- 詐騙群組有「暗樁」跟老師一搭一唱、貼獲利；留言區常見「目前 FB 只看你和 XXX」這類假帳號留言。
- 結論：**讚數、留言數本身分不出詐騙和小賣家；留言的「內容」才有用**，例如其他人留言提醒「騙子」「檢舉了」，或一堆不同帳號留「感謝老師」「已上車」。

## 2. 為什麼不能只看字眼

本專案在 Threads 實際看到的正常貼文：

| 正常貼文內容 | 只看字眼會誤判的原因 |
|---|---|
| 「原價賣，含運，只能先匯款，店到店」 | 「先匯款」是正常個人賣家常見條件 |
| 「出清」話題標籤＋「私了喔」回覆買家 | 「出清」「私訊」在二手交易很普遍 |
| 「大戶持股增加、外資投信同買，值得觀察」 | 一般股票討論，沒有誘餌或導流 |
| 「賣場放這邊可直接下單」＋官方賣貨便連結 | 用的是真正的 `myship.7-11.com.tw` |
| 提醒別人「有人說保證獲利叫你加 LINE，小心」 | 貼文在**引用**詐騙話術提醒大家 |

所以規則採用「**多個角度同時成立**才提示」，單一字眼永遠不觸發。

## 3. 判定角度（訊號類別）

| 類別 | 代表什麼 | 例子 |
|---|---|---|
| 誘餌 | 好到不真實的報酬或價格 | 保證獲利、免費送 iPhone |
| 導流 | 把人帶離平台 | 加 LINE 客服、LINE 群組連結、Telegram |
| 付款壓力 | 詐騙流程的付款／驗證話術 | 金流驗證、無卡提款、先付保證金 |
| 可疑連結 | 網址本身的證據 | 165 已知網域、仿冒賣貨便網域、縮網址 |
| 社群反應 | 其他使用者的留言，只當佐證（第 6 節） | 留言「騙子」「檢舉了」、多帳號「感謝老師」、多帳號留言幾乎相同 |
| 反向訊號 | 降低誤判 | 官方平台連結、貼文本身在提醒防詐 |

## 4. 字詞清單

**強**：官方來源明確點名、正常貼文幾乎不會出現。**弱**：正常貼文也常出現，只能當輔助。

### 4.1 誘餌

| 強度 | 字詞 |
|---|---|
| 強 | 保證獲利、穩賺不賠、穩賺、零風險、保本保息、包賺、只賺不賠、帶單、飆股群、免費領飆股、投資老師、股市老師、USDT／泰達幣＋搬磚或套利、內線消息；免費送／0 元＋iPhone、Switch、PS5、筆電、MacBook、AirPods；新開幕免費送 |
| 弱 | 跟單、助理、出金、日賺＋數字、月入＋數字、被動收入、倒店、清倉、一折、下殺、產地直送、現採現寄、因盛產、支持小農、名額有限、限時、最後幾組 |
| 不採用 | 投資、股票、獲利、主力、存股、出清、二手、團購、代購（太常見，誤判率高） |

### 4.2 導流

| 強度 | 字詞或網址 |
|---|---|
| 強 | LINE 客服、加客服、加入投資群組；LINE 群組邀請連結 `line.me/ti/g/`、`line.me/R/ti/g/`；Telegram（`t.me/`、飛機、TG） |
| 弱 | 加 LINE、加賴、LINE ID、私訊、私我、小盒子；`line.me/ti/p/`、`lin.ee/`（正常店家也用 LINE 官方帳號）；`wa.me/` |

### 4.3 付款壓力

| 強度 | 字詞 |
|---|---|
| 強 | 先付保證金 |
| 弱 | 只能先匯款、先匯款、匯款後寄出；金流驗證、實名認證、解除限制、帳號凍結、金流簽署、驗證費、無卡提款、OTP |
| 不採用 | 訂金（預購常見）、驗證碼（防詐提醒常提到） |

金流驗證這類話術原本列為強訊號。2026-10-15 實測發現誤判：詐團是在**私訊**裡講這些，公開貼文中出現時多半是受害者或熱心人在解釋手法，所以改為弱訊號。

### 4.4 可疑連結

| 等級 | 判斷 |
|---|---|
| 高風險 | 網域在 165 停止解析或假投資網站清單內 |
| 強 | 網域含 `myship`、`7-11`、`711`、`famiport`、`famistore` 等字，但不是官方網域（例如官方是 `myship.7-11.com.tw`） |
| 弱 | 縮網址：`reurl.cc`、`bit.ly`、`tinyurl.com`、`lihi.cc`、`lihi1.com`、`pse.is`、`ppt.cc`、`is.gd`、`cutt.ly`、`t.ly`；可疑頂級網域：`.top`、`.xyz`、`.cyou`、`.qpon`、`.icu`、`.vip` |

### 4.5 文字正規化

詐團會拆字規避，比對前先處理，證據仍顯示原文：

- 全形轉半形、英文轉小寫（Unicode NFKC）。
- 移除空白、零寬字元與夾在字中間的符號，例如「加 L I N E」「穩.賺」。
- 同義替換：「賴」「line」「Line」視為 LINE；「＋」「+」「加」視為加。

## 5. 判定邏輯

依把握程度分四級（使用者 2026-10-15 決定：很確定就一定是高風險，資料不足時保守地提醒）。

| 等級 | 條件 | 文案原則 |
|---|---|---|
| 高風險 | 任一**可驗證證據**（165 清單命中、仿冒超商平台網域），或 **2 個不同類別都有強訊號** | 「此貼文有多項高度可疑的詐騙特徵」＋證據 |
| 注意 | 至少 2 個不同類別的訊號，其中至少 1 個是強訊號 | 「此貼文包含可疑交易／投資話術」 |
| 提醒 | 只有 1 個強訊號，沒有其他類別佐證 | 「提到常見詐騙話術，交易前請查證」 |
| 資料不足 | 其他所有情況，包括只有弱訊號 | 不顯示；**不顯示「安全」** |

和規格書的差異：規格書第 5 節只讓「已知惡意網址」成為高風險，第 10 節「保證獲利＋先付保證金」是注意級。這裡依使用者決定，兩類強訊號同時出現（官方來源都說是「一定是詐騙」的話術）也算高風險；「提醒」是新增的等級。

補充規則：

- 同一類別再多個訊號也不會單獨觸發「注意」以上。
- 只有弱訊號時一律資料不足，即使跨類別，例如「只能先匯款＋私訊」。這是正常賣家最常見的寫法。
- 反向訊號：
  - 有官方平台連結時，「要求先匯款」不計分。
  - 貼文本身在提醒防詐（詐騙、小心、被騙、騙子、騙你、假裝、別亂點、不要相信、受害、報案、165 等），而且所有訊號都來自文字時，最多「提醒」。「不騙你」「不騙人」是詐騙常見說法，不算防詐語境。冒名帳號會故意加反詐字眼取信，所以連結證據照樣計分。
- 敏感度（FR-06 設定頁「顯示哪些標示」）：只調整顯示，不改判定。可選全部（提醒以上）、注意以上、只有高風險；帳號等級低於門檻時隱藏標示，判定與快取照舊。
- 「已檢查」標示（設定頁「顯示已檢查的帳號」，預設開啟）：資料不足的帳號可以選擇掛灰色「已看過 N 篇貼文、M 則留言，未發現可疑特徵」，只用來確認 FraudSignal 有在運作，不是判定等級。不用綠色、不用盾牌、不寫「安全」：規則只能找出可疑特徵，沒找到不代表安全，詐團也常先發正常貼文累積信任（養號）。使用者原本想要綠色「安全」，了解規格 US-05、第 5、7 節後改用這個做法。

實作：`src/engine/riskRules.ts`（字詞與網址規則）、`src/engine/riskEngine.ts`（正規化、比對、判定）。

### 5.2 165 清單實作

- `npm run update:blocklist` 下載兩份 CSV，輸出 `src/engine/blockedDomains.txt`。2026-10-15 版有 115,595 個網域，約 2MB。
- 打包成獨立 chunk，第一次遇到有外部連結的貼文才載入。
- **只比對完整網域**，不合併子網域：清單有上萬筆是同一主網域的子網域，但用「最後兩段」合併會誤收 `com.tw`、`it.com` 這類公共後綴，以及 `lovable.app`、`myqcloud.com` 這類共用主機，正常網站會被誤判。
- 腳本會排除 threads.com、line.me、myship.7-11.com.tw 等常用網域，防止資料錯誤造成大量誤判。

## 6. 留言與網軍（步驟 3b）

### 6.1 不做的事

- **讚數、留言數、轉發數**：不計分。第 1.6 節的研究指出互動數可以買，詐騙貼文重新上架後互動數也低，跟一般小賣家分不出來。等第 9 節的標註樣本收集好，再用數據確認。
- **確認按讚者、留言者是不是真人：不做。** 要逐一打開每個帳號的個人頁，等於在背景爬其他帳號，違反規格書第 8 節「只處理目前可見的公開內容」與第 2.2 節「不爬取帳號」。大量自動開頁也可能讓使用者的 Threads 帳號被限制，而且現在的網軍帳號外觀很像真人，準確度有限。
- **留言時間集中**：熱門貼文的正常留言也會在短時間內湧入，單獨看分不出網軍；內容相似度已涵蓋 bot 留言。標註樣本證明有用再加。

### 6.2 哪些算留言

只有**單篇貼文頁**（`/@帳號/post/ID`）看得到留言。主貼文往上第一個有多個子元素的祖先是對話區塊（2026-10-15 在有留言、回覆頁、沒有留言的貼文實測）：

- 區塊內、排在主貼文之後的貼文是留言；排在之前的是上層串文，不算。
- 下方「相關串文」推薦在區塊外，不算。
- 作者自己的留言不算。留言的留言目前也當主貼文的留言。
- 留言本身也照一般貼文判定，有風險時標示留言者，原因面板寫「留言」「查看留言」。

X 的單篇貼文頁（`/帳號/status/ID`）：主貼文與留言在同一個清單（登入後是對話時間軸、未登入是 `ul`），排在主貼文之後的是留言、之前的是上層串文；引用的貼文不算留言（2026-10-15 實測，未登入只看得到前 3 則留言）。留言後面若有「探索更多」推薦，標題之後的不算留言；實測的貼文沒出現這一段，標題結構是推測。

### 6.3 留言訊號（類別：社群反應）

| 規則 | 條件 | 強度 |
|---|---|---|
| 指認詐騙 | 其他帳號留言含「詐騙、詐團、騙子、騙錢、被騙、檢舉、報警、打／撥／報 165、165 專線」 | 2 個以上帳號：強；1 個帳號：弱（可能是同業或酸民） |
| 暗樁話術 | 2 個以上帳號留「感謝老師、老師帶、已上車、出金成功、賺了＋數字、翻倍了」 | 弱 |
| 網軍留言 | 3 個以上帳號的留言幾乎相同：只看文字與數字（網軍常換標點、表情符號），至少 8 字，雙字組 Jaccard 相似度 ≥ 0.8 | 弱 |

不算指認的寫法：「小心詐騙」「注意別被騙」這類泛用提醒、「不是詐騙」「沒被騙」這類否定句；「165」單獨出現不算（「165 公分」）。暗樁話術不收「賺到」「已私」「已加賴」，正常買賣留言很常見；「+1」「已私」這類短留言大量重複也很正常，所以網軍規則要求至少 8 字。

### 6.4 怎麼併入判定

留言**只當佐證**，用第 5 節同一套規則：

- 貼文本身沒有任何訊號時不看留言，避免「大家有被詐騙過嗎」這類貼文的作者被標示。
- 貼文在提醒防詐時不看留言，這類貼文的留言自然也會講到詐騙。
- 其他情況，社群反應算一個新類別。例如「只能先匯款＋私訊」（兩個弱訊號）加上 2 個帳號說「騙子」（強），就是 2 個類別、1 個強訊號 → 注意。
- 留言是捲動時陸續出現的，每多一則就重新判定主貼文。訊號只會增加，等級不會下降。

實作：`src/engine/riskRules.ts`（`COMMUNITY_WARNING`、`SHILL_PRAISE`）、`src/engine/riskEngine.ts`（`matchComments`）、`src/content/threadsAdapter.ts`（`getRepliedPostId`）、`src/content/main.ts`（收集留言、重新判定）。

## 7. 圖片文字（OCR）

使用者決定要做。詐團常把話術做成圖卡，內文只寫「詳情看圖」，只看文字會漏掉。

### 7.1 辨識方式

- 用 Tesseract.js 7（WebAssembly）在本機辨識繁體中文（`chi_tra`），免費、不上傳圖片。
- 所有檔案都打包在擴充功能裡，不從 CDN 載入（MV3 不允許遠端程式碼）：
  - worker：`tesseract.js/dist/worker.min.js`。
  - 核心：只帶 SIMD 版的 `tesseract-core-simd-lstm.wasm.js`（約 3.9MB），Chrome 91 起都支援。
  - 語言檔：`public/tessdata/chi_tra.traineddata.gz`（約 1.6MB），取自 `@tesseract.js-data/chi_tra` 1.0.0 的 `4.0.0_best_int`。Tesseract 依「langPath／語言.traineddata.gz」組網址，檔名不能加 hash，所以放 `public/`。
- content script 不能開擴充功能的 worker，所以辨識在離屏頁（offscreen document）執行：content script → 背景 service worker（建立離屏頁、轉送）→ 離屏頁。
- 權限：只多了 `offscreen`，安裝時不會跳警告。Threads 的圖片 CDN（`*.fbcdn.net`）回傳 `Access-Control-Allow-Origin: *`，X 的 `pbs.twimg.com` 回傳請求的來源，都不需要圖片網域權限（2026-10-15 實測）。
- manifest 的 CSP 要加 `'wasm-unsafe-eval'`，Chrome 預設的擴充功能 CSP 會停用 WebAssembly；這是 Chrome 允許的最低政策。
- Tesseract 預設用 `blob:` 網址開 worker，擴充功能的 CSP 不允許，要設 `workerBlobURL: false`。
- Tesseract.js 7 的語言檔若用 `{ code, data }` 物件傳入，初始化會誤用 `data` 欄位，所以不用這個寫法。
- 中文語言檔帶了舊引擎的參數，LSTM 版核心沒有，每次初始化都會用 `console.error` 印 8 行「Warning: Parameter not found」，被列進擴充功能的「錯誤」頁，但不影響辨識。改用含舊引擎的完整核心可以消掉，但實測辨識慢約 6 倍（同一張圖 1.2～2.2 秒 vs 0.2～0.4 秒）。所以在 worker 外包一層 `src/offscreen/tesseractWorker.js`，濾掉這一種初始化訊息。這個檔很小，要用 `?url&no-inline` 匯入，不然會被內嵌成 `data:` 網址，沒辦法帶參數。
- 同一個 worker wrapper 將 `Image too small to scale!! (...)` 與 `Line cannot be recognized!!` 精確轉為 `console.debug`：這是某個切出的文字區塊無法辨識的診斷，尺寸不一定是原始照片尺寸。保留其他錯誤及辨識 Promise 的失敗回傳；此處只調整記錄層級，不提升辨識率，也不代表整張圖片已完整辨識。

### 7.2 辨識哪些圖片

- 只辨識 `<picture>` 內的貼文照片；頭像、影片縮圖不在 `<picture>` 內（2026-10-15 實測）。Threads 的貼文照片沒有替代文字（alt 是空的），不能直接拿來用。
- 從 srcset 挑寬度不超過 1080 的最大張：小字看得清楚，再大只會變慢。實測 1080 寬約 1.7～2 秒、720 寬約 1.2 秒，第一次載入引擎約 0.6 秒。
- X 只辨識 `pbs.twimg.com/media/` 的貼文照片，改用 `format=jpg&name=medium`（1200 寬）：預設的 webp 不確定 Tesseract 能讀，`small`（680 寬）看不清小字。頭像、連結卡片縮圖、影片縮圖不辨識。
- 每篇最多 3 張：詐騙圖卡的重點通常在前面，輪播十張全辨識太吃 CPU。
- 一次只辨識一張；後進先出，快速捲動時先辨識剛進入畫面的貼文（規格書第 9 節）。已離開畫面的貼文仍會辨識，之後若要更省 CPU 再改成可取消。
- 30 秒沒回應就放棄這張，不卡住後面的佇列。全部失敗時不存結果，下次載入頁面再試。

### 7.3 怎麼併入判定

- 先用內文判定、馬上顯示，圖片辨識完再重新判定；等級只會升高。
- 辨識出的文字走第 4、5 節同一套文字規則，證據標示「圖片文字」（`source: 'image'`）。Tesseract 會在中文字之間加空白，送回前先去掉；第 4.5 節的正規化本來也會去空白。
- 圖片跟內文命中同一條規則時只列內文。
- 圖片在提醒防詐（第 5 節的提醒情境）時，跟內文一樣最多只到「提醒」。
- 辨識過圖片的貼文，不論有沒有風險都存進快取，連同辨識出的文字（`imageText`），重新整理後不用重新辨識；留言讓主貼文重新判定時也會一起算。
- 中文模型辨識英文圖片時會出現零散的錯字；規則比對的是完整詞組，零散錯字不會誤觸。

實作：`src/content/threadsAdapter.ts`（`pickSrcsetUrl`、照片網址）、`src/content/imageText.ts`（佇列）、`src/background/main.ts`（建立離屏頁）、`src/offscreen/main.ts`（Tesseract）、`src/engine/riskEngine.ts`（`imageText` 參數）。
